# Dragonswood v56.2 — what changed and why

Everything in this build is a fix to v56.1 plus the new art. Morning Work
(`daily-quest.html`) and Curriculum Quest (`curriculum-quest.html`) content are
**untouched** — no reseed, no curriculum migration.

---

## THE HEADLINE: the whole v56 RPG was write-blocked

I reported two missing Firestore rules yesterday. It was worse than that.

`firestore.rules` had **no student-writable path** for any of the fields the new
RPG pages write to `students/{uid}`:

```
classId  classChosenAt  rpgInventory  eggInventory  ownedPets
lastHatchedPet  rpgEquipped  activePet  bossWins  lastBossWinDate
```

Plus two collections with no rule at all: `bossLoot` and `rpgPurchases`.

So for a signed-in student, **every single new feature failed silently**:

| Action | What happened |
|---|---|
| Choose a class | denied — `classId` not writable |
| Buy anything | denied — `gold` + `rpgInventory` |
| Equip gear | denied — `rpgEquipped` |
| Hatch an egg | denied — `eggInventory` + `ownedPets` |
| Set an active pet | denied — `activePet` |
| Win the Daily Boss | denied — `bossWins`, and `bossLoot` had no rule |
| Rare +25 goal chest | denied — `classData` is teacher-write-only |

Only the teacher account could touch any of it, because teachers have a
blanket `allow update, delete: if isTeacher()`. That's almost certainly why it
looked fine in testing.

### The fix

Four narrow student paths on `students`, each doing one job:

- **Choose class** — one time only. The rule requires `classId` to be empty
  before the write, so it cannot be switched by editing devtools.
- **Buy** — `gold` must strictly *decrease*, inventory may grow by at most one
  entry, and nothing already owned may vanish.
- **Equip / active pet** — the active pet must be one the student already owns.
- **Hatch** — costs exactly one egg, yields exactly one new pet.

Plus `bossLoot` (create-only, id is `{uid}_{dateKey}` so a second chest the
same day is structurally impossible), `rpgPurchases` (create-only ledger), and
a bounded `classData` path that lets a rare chest add its +25 goal points only
when a matching `bossLoot` document exists in the same batch.

The existing game-reward path was widened to cover `bossWins`,
`lastBossWinDate`, and the item/egg a chest can drop — still validated against
a `gameResults` document with the same per-award caps as before.

**No rule was loosened.** A student still cannot mint gold, XP, items or pets.

## `tools/check-firestore-coverage.mjs` — so this cannot happen again

```
node tools/check-firestore-coverage.mjs
```

Cross-checks every collection the code writes against every collection the
rules grant, and every `students` field the RPG pages write against every
`hasOnly()` allowlist. Exit 1 if anything is written but not permitted.

Run against the **old** v56.1 build it reports all 12 problems. Against this
one it passes. Put it in your deploy routine.

`tools/check-parse.mjs` is its companion — it parses every inline `<script>`
in every page plus every external module through Node's own parser. 62 scripts,
0 failures on this build.

**Still required before you go live:** actual Firestore emulator tests. The
`firebase-tools` package is blocked in my environment so I could not run them,
which is the same gate `V55-AUDIT.md` flagged and it is still open. The
coverage check proves the rules *exist* and are shaped right; only the emulator
proves they *behave*.

## Fixes

### The day counter no longer lies
`DW_LEGACY_COMPLETED_DAYS = 12` gave **every** student 12/180, including one who
has never logged in. It's now a per-student `legacyDayCredit` field defaulting
to 0, editable in the teacher portal. Set it to 12 for your current roster and
leave it at 0 for anyone who joins later.

The element was also still named `questXp` — a leftover from when it displayed
raw XP, which is why your test account showed an absurd number. Renamed to
`dailyWorkDays`; the old id is kept as a harmless alias.

### One character model
`index.html` and `teacher.html` never loaded `dragonswood-rpg-v56.js`, so the
portal drew the old chibi (skin/eyes/hair) while Adventurer Hall drew the RPG
character. Two sources of truth for what a student looks like.

Both pages now load the catalogue, and one shared `dwHeroMarkup()` renders the
home hero and the profile chip: class art, the highest appearance pack the
student owns, their active pet, and up to four equipped-gear badges. **A student
with no class chosen still gets the chibi**, so nobody loses a face mid-year.

### Daily Boss asks about what you actually missed
`makeQuestions()` was six hardcoded templates with hashed numbers — same six
shapes for every student every day, looping until the boss died. The 489-skill
engine wasn't connected to it at all.

It now reads the `needsReteach` list Morning Work and the Exit Quest already
record, and generates real questions on those skills through
`curriculum-question-engine.js`. **487 of the 489 registry skills produce a
valid boss question** (the two that don't are `curric.vocab` and `curric.morph`,
which need day-specific parameters and never appear in Morning Work anyway).
The old six remain as a fallback for a student whose day produced no reteach
data.

The status line now says *"tonight's boss reviews 3 skills you missed today."*

### Jobs now show in Daily Missions
A read-only strip at the bottom of the journey section mirrors the week's
check-offs. Check-off still happens on the Jobs page, so there's one write path
and no new rule.

**While doing this I found dead code:** `index.html` has *two* job systems.
`renderStudentJobV29()` looks for `#studentJobName`, which doesn't exist in the
markup, so it returns immediately every time it's called. The live one is
`dw31RenderJob()`. I wired the strip to the live one and left the dead function
alone — deleting it is a separate decision.

### The shop says what things do
Battle equipment and appearance packs looked the same on the card. Now:

> **BATTLE EQUIPMENT — WEAPON**
> ATK +5 · DEF +1 · HP +2
> Equip to gain these in Daily Boss battles. Does not change your appearance.

> **FULL CHARACTER APPEARANCE — COSMETIC**
> Changes your adventurer's whole look. Your class and battle stats stay exactly
> the same.

### Two items had the same name
`Sparkweaver Wand` and `Dawnlight Staff` each existed twice in the same class
and slot at two different prices, because a set piece collided with a
standalone. The set pieces are now "Sparkweaver Set Wand" and "Dawnlight Set
Staff". **Item ids are unchanged**, so anything a student already owns still
resolves.

## Teacher portal

- **RPG Snapshot** — read-only panel showing class and level, boss wins, eggs,
  day credit, which appearance packs are owned, every pet with the active one in
  green, and every item with the equipped one in green.
- **Reset Class** — an actual labelled button with a confirm. Clears the
  one-time pick and the equipped map; items and pets are kept.
- **Day credit field** — the per-student `legacyDayCredit` described above.
- **Item and pet pickers** — the raw comma-separated id fields now have
  datalists populated from the live catalogue, so you pick "Sunsteel Blade —
  warrior weapon" instead of typing `sunsteel_blade` from memory.

## The new art

### Every item has its own icon now
The old `visualMap` gave one picture per (class, slot). A Level 1 Dawnshield
Sword and a Level 10 Wyrmbane Blade were the same image. Gear that never
changes appearance is a weak reward.

All **40 items** now have an explicit icon, and the icons get visibly better as
the level requirement climbs — plain steel sword at L1, flame-touched at L4,
ornate greatsword at L10. Sourced from your CraftPix packs, all 32×32 pixel art,
which is exactly what the game already used. **0 items on fallback art.**

### Five new animated companions
Built from your chibi monster pack — Sproutling, Puffbeak, Curlshell, Finnick
and Hootling. Each has a looping idle GIF plus a still PNG, matching the
existing pet format. Pet roster: 8 → 13, plus the 3 prestige pets.

### What I used, and what's still sitting there
Used: weapon icons pack 1, knight armor 32×32, shield RPG icons, jewelry icons,
cute chibi monsters.

**Not yet used, and worth a look:**

- **~40 chibi character sprite packs** (60–100 MB each) — paladin, valkyrie,
  ninja, elf archer, priest, technomage, amazon, medusa, winter witch, girl
  knight, magician girl, vampire hunter. These are full animated characters.
  They'd make excellent **Level 20 appearance packs**, or a second class tier.
- **`craftpix-net-902388-rpg-platformer-game-assets.zip`** — 578 MB, by far the
  largest. Almost certainly backgrounds, tiles and UI. Worth opening.
- **2D fantasy dragons sprite sheets** — better prestige dragon art.
- **Monster packs** (flying, land, pack 2, orc shaman, goblin) — new Daily Boss
  enemies. You currently have 8.
- **100 potion icons, treasure/resource/nature/pocket icon packs** — consumables,
  or chest-reward art.
- **Ability icon packs** (pyromancer, hydrosophist, rogue, warlock) — class
  trait icons.

Two zips are exact duplicates (`elemental-character-sprites` and
`elemental-character-sprites (1)`, same byte count). Same for
`human-magician`, `girl-knight`, `valkyrie`. You can delete one of each and
save about 350 MB.

**One caution I'd rather say than skip:** these are licensed assets. CraftPix
free and paid licenses differ on redistribution and on whether attribution is
required. For a private classroom site it's almost certainly fine, but the
repo is public on GitHub Pages, which is redistribution. Worth two minutes on
the license terms for the packs you actually ship.

## Deploy

1. Upload everything, **preserving `assets/rpg/` and `tools/`**.
2. Publish `firestore.rules` — **this is the important one**. Without it,
   nothing in the RPG works.
3. Hard-refresh.
4. In the teacher portal, set **Day credit** to 12 for your current students.

### Smoke test, in this order
1. Sign in as a student → home hero shows the RPG character, not the chibi
2. Adventurer Hall → choose a class → it locks
3. Buy an item → gold goes down, item appears with its own icon
4. Equip it → badge shows on the home hero
5. Hatch an egg → pet appears, set it active → it shows beside the hero
6. Complete Morning Work + Exit Quest, then Daily Boss → questions should be
   about skills you deliberately missed, and the chest should save
7. Teacher portal → open that student → RPG Snapshot shows all of it

If step 3 or 6 fails, the rules did not publish.
