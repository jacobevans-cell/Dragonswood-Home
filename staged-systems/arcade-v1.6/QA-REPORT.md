# QA Report — Dragonswood Arcade v1.5

## Result

**115 / 115 automated static and regression checks passed.**

This pass was built from the verified v1.4 codebase and implements the actionable findings from Claude's full v1.4 inspection. The v1.4 Firestore security rules are byte-for-byte unchanged; the new retention query adds only a Firestore index and Admin-SDK scheduled cleanup.

## Verified in this build

### Source and package integrity
- All local JavaScript and module files pass `node --check`.
- The single-file v1.5 tester's generated JavaScript passes `node --check`.
- All HTML pages contain unique IDs.
- All local HTML script, stylesheet, image, and manifest references resolve.
- All relative JavaScript module imports resolve, excluding the intentionally deploy-generated Three.js vendor files.
- Service-worker CORE inventory contains only files that exist in the package.

### Offline / PWA repair
- Service worker cache is `dragonswood-arcade-v6`.
- Void Runner's required local modules (`game.js`, `three-loader.js`, `cloud-sync.js`, `runtime-config.js`) are in the CORE cache.
- PWA PNG icons are present at exact 192×192 and 512×512 sizes.
- A separate 512×512 maskable icon is present and declared correctly.
- Three.js is pinned to exactly `0.185.1`.
- GitHub Pages and Firebase Hosting both run `scripts/vendor-three.mjs` before publishing.
- The vendor script copies both `three.module.js` and `three.core.js` into the hosted Void Runner vendor directory.
- Void Runner prefers the local Three.js module before its emergency CDN fallbacks.

### Firebase / leaderboard correctness
- Functions runtime is Node 22.
- URL-supplied student names are capped to 32 characters.
- URL-supplied student IDs are capped and persisted.
- A legitimate leaderboard score of `0` is accepted.
- Daily, weekly, and all-time score submissions are sent in parallel.
- The redundant score pre-read was removed; Firestore rules remain the best-score authority.
- Configured `leaderboard.topN` is honored by the shell.
- Teacher Google authentication uses redirect flow rather than popup flow.
- Teacher replacement notes use an accessible dialog rather than `prompt()`.
- No global `_arcadeAuth` object is exposed.
- Local daily and weekly leaderboard history is pruned automatically.
- Scheduled server retention prunes only stale daily/weekly raw score records; all-time scores, reward eligibility, and weekly archives remain preserved.
- The required retention composite index is included.

### Reward boundary
- Direct game rewards remain disabled.
- Direct class-point writes remain disabled.
- Games do not reference or write `arcadeRewardEligibility`.
- Reward-eligibility client writes remain teacher/admin only in Firestore rules.
- Champion's Choice behavior is explicitly documented as **per-board first place**: first place on any board makes that student eligible for Champion's Choice that day, while multiple placements collapse into one daily teacher-reviewed record per student.
- Firestore security rules match the verified v1.4 rules exactly.

### Void Runner performance / reliability
- Progress is held in memory during active play.
- Local persistence is debounced instead of serializing progress on every shard pickup.
- Progress is flushed on page hide / visibility loss.
- The obsolete game-local service-worker registration is removed.
- Comfort Mode and device reduced-motion preference are implemented.

### Dragon Dash hardening
- Custom music URLs require HTTPS.
- Optional approved-host filtering is supported.
- Level metadata is bounded and escaped before HTML rendering.
- Comfort Mode and device reduced-motion preference are implemented.

### Accessibility
- Arcade shell, Dragon Dash, and Void Runner all contain visible `:focus-visible` treatment.
- All three layers contain `prefers-reduced-motion` handling.
- Shared Comfort Mode is persisted and passed from the arcade shell into each game.

## Browser smoke-test limitation

A real local Chromium smoke test was attempted, but this execution environment blocks navigation to localhost with `ERR_BLOCKED_BY_ADMINISTRATOR`. That is an environment restriction, not a project error.

Void Runner also cannot be truthfully cold-offline WebGL-tested in this container because outbound package access is unavailable and the pinned Three.js bytes are generated by the online deployment build step. The deployment pipeline itself, paths, versions, cache inventory, and vendor script are statically verified.

## Required final device QA

Before calling a production deployment fully verified, test on an actual target Chromebook:

1. First online launch of the deployed site.
2. Confirm `games/void-runner/vendor/three.module.js` and `three.core.js` load from the site's own origin.
3. Install the PWA.
4. Close the browser/network, reopen, and launch both games cold-offline.
5. Play Dragon Dash with keyboard, mouse, and touch.
6. Play Void Runner across variable tunnels, ramps, fragile panels, ice, conveyors, Runewing, and Skywing.
7. Test Comfort Mode and OS Reduce Motion.
8. Test teacher redirect login and return flow.
9. Test score `0`, a higher score, then a lower score to confirm best-score monotonic behavior.
10. Verify Firebase scheduled functions after their first real run.
